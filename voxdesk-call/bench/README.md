# VoxDesk — Multi-Vertical Workflow Evaluation Benchmark (`bench/`)

> **Disclosure (`self_reported: true`)**:
> Results in `bench/results/` are **self-reported** runs generated by `bench/run_bench.py`. In offline CI (`evaluation_mode: "deterministic_seeded_offline"`), `provider_fakes: true` is stamped on the JSON output because no live OpenAI/Anthropic API keys are present. Buyers and technical reviewers should re-run with `--live-llm` and/or an independent third-party evaluator (Section 4) before treating scores as external model benchmarks.

## 2. Scoring Methodology & Confidence Intervals

Each scenario requires **both** gates to pass (`workflow_passed = tool_eval.passed AND judge_passed`):

1. **Exact Tool-Call & Argument Verification (`evaluate_tool_calls`)**:
   - Every expected tool in `expected_tool_calls` must fire in causal order (`verify_patient_identity` / `verify_account_otp` *before* any read or mutation tool) with every `required_args` key/value matching.
   - Any unauthorized extra mutation tool call (for example, booking or reading balances when `verified: false` or `otp_verified: false`, or issuing an out-of-policy refund on `eligible_return: false`) is an automatic **FAIL**.
2. **Conversation Judge (`SimulatedCaller.judge_conversation`)**:
   - Evaluates the multi-turn transcript against `goal` and `pass_criteria`.
3. **95% Wilson Score Confidence Interval (`wilson_ci_95`)**:
   - Reported overall (`N = 100`) and per vertical (`N = 34 / 33 / 33`) using two-sided `z = 1.96`, bounded strictly inside `[0%, 100%]`.

## 3. Methodological Limits

- **Seeded Offline vs. Live LLM Variance**: Offline mode (`--seed 20261107`) exercises deterministic turn generation plus a seeded noisy-channel entity perturbation rate (`--noisy-error-rate 0.08` on `noisy_background` / `frequent_barge_in` personas). Live LLM accuracy varies with temperature, upstream model snapshots, and real ASR word-error rate (WER).
- **Text-Turn vs. Acoustic PSTN Layer**: `bench/run_bench.py` evaluates dialog policy, guardrails, and tool accuracy. End-to-end G.711 carrier audio latency and acoustic barge-in must be measured separately with `scripts/run_real_call_study.py` (`docs/LATENCY_BENCHMARK.md`).
- **Self-Authored Rubrics**: Scenarios and reference policies live in the same repository; independent evaluation is therefore supported out of the box below.

## 4. Reproduction & Running a Third-Party Evaluator

### A. Reproduce the Baseline Seeded Run (`provider_fakes: true`)
```bash
python bench/run_bench.py --seed 20261107 --output bench/results/2026-11-07.json
```

### B. Run Against Live OpenAI / Anthropic Models (`provider_fakes: false`)
```bash
export OPENAI_API_KEY="sk-..."
python bench/run_bench.py \
  --live-llm \
  --llm-provider openai \
  --llm-model gpt-4o-mini \
  --seed 20261107 \
  --output bench/results/live-$(date -u +%Y-%m-%d).json
```

### C. Benchmark an External / Third-Party Agent Over HTTP
Implement a thin adapter endpoint accepting `POST` JSON `{"scenario_id", "vertical", "turn_index", "caller_utterance", "context_variables", "transcript"}` and returning `{"reply": "...", "tool_calls": [{"name": "...", "args": {...}}]}`:

```bash
python bench/run_bench.py \
  --external-agent-url https://evaluator.example.org/v1/turn \
  --live-llm \
  --seed 20261107 \
  --output bench/results/third-party-$(date -u +%Y-%m-%d).json
```

### D. Score Transcripts with Promptfoo / Inspect AI / DeepEval
Every YAML file in `bench/scenarios/*.yaml` uses plain ISO YAML (`persona`, `goal`, `expected_tool_calls`, `pass_criteria`), and `bench/results/<date>.json` records per-scenario `tool_eval` and `judge_score` so external LLM judges (e.g., Anthropic Claude Sonnet judging an OpenAI GPT-4o agent) can re-grade transcripts directly without importing VoxDesk code.
