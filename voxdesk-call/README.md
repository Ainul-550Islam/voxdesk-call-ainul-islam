## Development setup

Use Python 3.12 and the pinned requirements. Copy `.env.example` to `.env` and supply deployment-specific secrets before starting services.

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements-validation.txt
make up
make migrate
python -m scripts.create_owner --help
```

Run `make verify-truth`, `make contracts-check`, and the application test suite before release. External-provider credentials must be supplied separately; local contracts do not establish real delivery.

Historical reports are audit records, not current capability promises. See `reports/PART_0_REPORT.md` for this pass and residual gates.

## Commit policy

Use the requested task ID in each scoped commit (for example, `P0-08: remove verified generated UI tails`). Do not combine unrelated staged work, generated padding, secrets or downloaded dependencies. Truth guards run in CI; never expand a shrink-only exception to hide a regression.
